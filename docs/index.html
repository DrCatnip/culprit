Why it broke

Explained by Nemotron 3 Ultra (offline stand-in) · Confidence: high

Paise refactor switched to Python round(), which rounds .5 to even

This commit moved money maths to integer paise. round_rupees now calls Python's round(paise / 100). Python rounds halves to the nearest even number, so 42.5 becomes 42 but 43.5 becomes 44. The old code used Decimal with ROUND_HALF_UP, which always rounds 50 paise up.

billing/money.py

Before

return int(to_decimal(amount).quantize(ONE_RUPEE, rounding=ROUND_HALF_UP))

After

return round(to_paise(amount) / PAISE_PER_RUPEE)

Why tests missed it

The tests only used 43.50, which rounds up either way. No test had an even rupee amount with exactly 50 paise.

Fix idea

Keep integer paise, but round half up on purpose: divmod by 100 and add 1 when the remainder is 50 or more.
